## 2. Safe Production Verification Procedures

### Procedure A: Passive Browser Network Inspection (No Synthetic Data)
Verify standard event firing and client identifier assignment without transmitting mock sales:
1. Open Google Chrome in Incognito mode.
2. Open Chrome DevTools (`F12`) and navigate to the **Network** tab.
3. Filter requests by: `collect?v=2`
4. Navigate to `https://aitoolgems.tech/`.
5. **Assertions on initial load:**
   - Confirm HTTP 204 response from `https://region1.google-analytics.com/g/collect` (or `www.google-analytics.com`).
   - Confirm query parameter `tid` equals `G-NQJCMDCLLP`.
   - Confirm query parameter `en` equals `page_view`.
   - Confirm `cid` parameter matches standard Google client ID format: `^[0-9]+\.[0-9]+$` (e.g. `123456789.987654321`).
   - Assert that no artificial prefixes (`SYNTH_`, `TEST_`, `SEED_`) appear in `cid`.

### Procedure B: Non-Purchase Interactive Event Triggering
Verify user engagement and lead generation tracking on a live tool page:
1. Navigate to `https://aitoolgems.tech/tools/chatgpt/`.
2. Scroll through the page and observe `scroll` event payload (`epn.percent_scrolled=90`).
3. Click the **"Buy via WhatsApp"** CTA button.
4. **Assertions on WhatsApp CTA click:**
   - Inspect the outgoing `collect` request.
   - Confirm event name `en=click_whatsapp_checkout` (or `begin_checkout`).
   - Confirm event parameters:
     - `ep.item_name=ChatGPT Plus`
     - `ep.price=1200`
     - `ep.currency=PKR`
     - `ep.payment_type=WhatsApp Assisted`
   - Confirm no synthetic purchase transaction is transmitted.

### Procedure C: Google Consent Mode v2 Verification
Verify that tracking respects privacy defaults:
1. Clear cookies and load `https://aitoolgems.tech/`.
2. Inspect the first `collect` request query parameters:
   - Verify `gcs` parameter reflects consent status:
     - `G100`: Consent denied / pre-consent default.
     - `G111`: Consent granted for analytics and advertising storage.
3. Verify that zero IP addresses or personal identifiers are collected in custom event dimensions.

### Procedure D: Offline Conversion Importer Validation Server
To test backend Measurement Protocol payloads generated by `ga4_agent` without logging fake data to reports:
1. The `ga4_agent` supports targeting Google's official Debug/Validation endpoint:
   `https://www.google-analytics.com/debug/mp/collect`
2. Google's validation server parses the payload, validates syntax, parameter names, and constraints, and returns a JSON diagnostic response (`validationMessages`) without recording any hit in production metrics.
3. Verified by unit tests in `ga4_agent/tests/test_ga4_agent.py` (30 tests passing).
